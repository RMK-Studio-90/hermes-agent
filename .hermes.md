# Hermes Agent — Working Rules (condensed)

Condensed from `AGENTS.md` for Hermes sessions, which load this file INSTEAD
of `AGENTS.md` (`.hermes.md` wins context-file priority). `AGENTS.md` stays
the authoritative full guide; when the two disagree, `AGENTS.md` wins. Before
changing a subsystem listed in the index at the bottom, `read_file` that
`AGENTS.md` section — the details there are binding, not optional.

**Never give up on the right solution.**

## What Hermes is — the two lenses for every change

Hermes is a personal AI agent: one agent core behind a CLI, a messaging
gateway (~20 platforms), a TUI and an Electron desktop app; it learns across
sessions (memory + skills), delegates to subagents, runs cron jobs, and
drives a terminal and browser. It grows through plugins and skills, not core.

- **Per-conversation prompt caching is sacred.** Never mutate past context,
  swap toolsets, reload memory or rebuild the system prompt mid-conversation
  (only context compression may). System prompt stays byte-stable for the
  conversation. Strict role alternation: never two same-role messages in a
  row, never a synthetic user message injected mid-loop. Slash commands that
  change prompt state default to next-session effect with an opt-in `--now`.
- **The core is a narrow waist.** Every model tool ships on every API call.

## Contribution rubric

Want: real bug fixes (reproduce on `main`, name the exact line, fix the whole
bug class incl. sibling call paths); expansion at the edges (platforms,
providers, models, desktop/TUI features) wired into `hermes tools` /
`hermes setup`; god-file extraction refactors; behavior-contract tests; E2E
validation with real imports against a temp `HERMES_HOME` for resolution
chains, config propagation, security boundaries, remote backends, I/O;
contributor credit preserved (cherry-pick, don't reimplement).

Reject: speculative hooks with no consumer; new `HERMES_*` env vars for
non-secret config (`.env` = secrets only, behavior goes in `config.yaml`);
a new core tool where terminal + file or a skill works; `offset`/`limit`
pagination on instructional tools (skills, prompts); "fixes" that kill the
feature they secure; telemetry/attribution without an opt-in gate;
change-detector tests; cache breaks; dead code wired in without E2E proof;
plugins touching core files; third-party-product plugins in-tree (ship as a
standalone plugin repo; `plugins/memory/` is closed to new providers).

Verify the premise before calling something a bug: limitations are often
deliberate (`git log -p -S "<symbol>"`); trace the real runtime before
trusting a rationale; an "obvious" missing piece can be load-bearing absence;
don't resurrect approaches maintainers moved past. When intent is unclear,
ask.

**Footprint ladder** (pick the highest rung that works): extend existing code
→ CLI command + skill → service-gated tool (`check_fn`) → plugin → MCP server
in the catalog → new core tool (last resort). 3+ PRs integrating the same
category → design an ABC + orchestrator instead.

**Surface capability is a property of the SESSION, not the process env.**
GUI-only tools live in a named toolset (`desktop_ui`, `project`) folded in by
the session's platform, never gated on `HERMES_DESKTOP=1`. `check_fn` answers
reachability or opt-in only (it's TTL-cached process-wide). Test that the GUI
session gets the tool with the env var absent.

## Development & testing

- `source .venv/bin/activate` (or `venv`).
- **Always run tests via `scripts/run_tests.sh`** (CI parity: creds unset,
  TZ=UTC, per-file subprocess isolation). File-granular: `scripts/run_tests.sh
  tests/x/test_y.py -k name`. A `⚠ FLAKY` report is a bug to fix.
- Tests must not write to `~/.hermes/` (autouse fixture redirects
  `HERMES_HOME`); profile tests also mock `Path.home()`.
- **Never read source files in tests** (banned) — extract logic into a
  pure/DI-testable function and call it.
- **No change-detector tests** (model lists, config version literals,
  counts) — assert invariants/relationships instead.
- **Don't fake the host OS**: use `@pytest.mark.linux_only` / `macos_only` /
  `windows_only`, never a bare `skipif` or `sys.platform` patching.
- Tests about `package.json`/TS/JS artifacts belong in vitest, not pytest.
- TypeScript: nanostores for shared state (`useStore` to render,
  `$atom.get()` in actions), no monolithic hooks, interfaces for props,
  table-driven over condition ladders, `onClick={() => void save()}`.
  TUI: `cd ui-tui && npm run typecheck && npm run lint && npm test`.

## Rules you will hit most

- **Profiles:** always `get_hermes_home()` for state paths and
  `display_hermes_home()` for user-facing paths (both from
  `hermes_constants`); never `Path.home() / ".hermes"`. Exception: profile
  roots are HOME-anchored (`_get_profiles_root()`) on purpose.
- **Multiplex profile secrets fail closed:** under
  `gateway.multiplex_profiles`, read profile env/authz via
  `_get_scoped_secret()` / `_auth_env()` / `_platform_gate_env()`; a scoped
  miss returns the default, never falls through to `os.environ`.
- **Config:** new `config.yaml` keys go in `DEFAULT_CONFIG`
  (`hermes_cli/config_defaults.py`); bump `_config_version` only for real
  migrations. Secrets go in `OPTIONAL_ENV_VARS`. Know your loader:
  `load_cli_config()` (CLI), `load_config()` (subcommands), raw YAML
  (gateway runtime; TUI live-reload treats missing keys as unset).
- **Adding a tool:** first settle the footprint question. Local/custom tools
  are plugins (`~/.hermes/plugins/<name>/`, `ctx.register_tool`). Core: a
  `tools/x.py` with `registry.register(...)` (handler returns a JSON string)
  AND a toolset entry in `toolsets.py`. Schema descriptions must not name
  tools from other toolsets (add cross-refs dynamically in
  `get_tool_definitions()`); profile-aware paths via `display_hermes_home()`.
- **Slash commands:** one `CommandDef` in `COMMAND_REGISTRY`
  (`hermes_cli/commands.py`) feeds CLI, gateway, Telegram, Slack, help and
  autocomplete; add handlers in `cli.py` / `gateway/run.py`.
- **Gateway control commands** must bypass BOTH message guards
  (`gateway/platforms/base.py` pending queue and `gateway/run.py`) and be
  dispatched inline.
- **Streaming (stream-is-the-message adapters):** draft frames must be
  prefix-stable; `finish(final_text)` carries the authoritative final;
  interim sends set `metadata["_interim_send"] = True`; reconcile finals by
  `edit_message`, not a plain send. Tests: `tests/gateway/test_stream_final_contract.py`.
- **Process identity:** never classify processes by argv substrings — use
  `gateway.status.looks_like_gateway_command_line` /
  `hermes_cli.update_cmd._hermes_holder_subcommand`; derive flag sets from
  the parser; match full cmdlines.
- **Menus** use curses (`hermes_cli/curses_ui.py`). No `\033[K` in spinner
  output (pad with spaces). `_last_resolved_tool_names` is process-global and
  temporarily stale during subagent runs.
- **Dependencies:** every PyPI dep bounded `>=floor,<next_major` (pre-1.0:
  `<0.(minor+2)`); git deps and GitHub Actions pinned by SHA; run `uv lock`.
- **Squash merges from stale branches revert fixes** — update from `main`
  first and check `git diff HEAD~1..HEAD` for unexpected deletions.

## Subsystem invariants (short form — read the AGENTS.md section before editing)

- **Delegation:** children get a focused brief (goal + `context` + workspace
  project-context files), `skip_memory=True`, no `delegate_task` / `clarify`
  / `memory` / `send_message` / `cronjob`, no kanban; toolsets inherited from
  the parent minus `delegation.inherit_exclude_toolsets`. No model-facing
  `toolsets` param. Depth is flat by default (`max_spawn_depth: 1`);
  concurrency default 10. Child summaries are self-reports — verify side
  effects before reporting success. Durable work → `cronjob` or background
  terminal, not background delegation.
- **Cron:** memory enabled (`skip_memory=False`), no background review fork;
  deliveries land in their own cron session (not mirrored into the gateway
  session); inactivity timeout (default 600s); file lock prevents duplicate
  ticks.
- **Curator:** only touches `created_by: "agent"` skills; never deletes (max
  is archive); pinned skills exempt.
- **Skills:** SKILL.md `description` ≤ 60 chars, one sentence, ends with a
  period; reference native tools by name in prose; audit `platforms:`
  against script imports; credit the human author first; modern section
  order; helpers in `scripts/`; tests in `tests/skills/`. Heavy/niche skills
  go in `optional-skills/`.
- **Plugins:** never modify core files for a plugin — widen the generic
  plugin surface. Keep plugin APIs additive (kwargs payloads, no removed ctx
  methods, deprecations warn once and survive two minor releases).
- **Bot Mode:** one bot = one canonical chat identified by NAME (profile +
  session titled exactly "Bot Chat"), resolved by registry lookup every
  click, adopt-before-mint on create. Never reintroduce a stored session-id
  pointer, recency, or visibility as the bot row's target.
- **Update pipeline:** plan → snapshot (every profile, identical set) →
  apply (ZIP fallback only on git failure, refuses dirty trees) → fleet-wide
  drain-first restart → verify running `code_sha` → write a receipt on every
  exit path. Don't add process-scan heuristics without reading #92091.
- **Gateway vs desktop:** the messaging gateway outlives the app by design
  (detached spawn); don't re-parent it or widen the Windows tree-kill.
- **Desktop slash palette** hides noisy built-ins only; skill and
  `quick_commands` extensions must stay in both completion paths
  (`isDesktopSlashExtensionCommand`).
- **Dashboard `/chat`** embeds the real `hermes --tui`; never rebuild the
  transcript/composer in React.
